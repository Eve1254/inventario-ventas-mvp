# ETL de inventario — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Ejecución local autorizada; continuar en la carpeta establecida.

**Goal:** Importación masiva revisable, repetible y transaccional para sustentar un ETL real.
**Architecture:** `imports.py` extrae/transforma/carga y exporta informe/plantilla. `import_ui.py` presenta vista previa y confirma la carga. Se reutilizan validadores de inventario y helpers CSV existentes. `ui.py` incorpora la quinta pestaña y refrescos posteriores.
**Tech Stack:** Python, csv, SQLite, Tkinter, unittest; sin dependencias nuevas.
**Spec:** `docs/superpowers/specs/2026-10-28-etl-design.md`.

## Global Constraints

Solo insertar nuevos productos; nunca ajustar existentes. CSV UTF-8, ;, cuatro columnas, 2 MiB, 2000 registros. Validaciones compartidas, dinero entero, vista previa sin escrituras. Todos los errores del lote bloquean carga. Cargar exactamente valores revisados; transacción única y revalidación de códigos bajo bloqueo. Datos de pruebas solo temporales.

## Review Focus

1. Archivos vacíos, encabezados ambiguos, filas con columnas faltantes/extra, comillas/saltos y codificación incorrecta.
2. Códigos duplicados tras normalizar; archivo repetido después de vender; no restaurar stock ni modificar precio.
3. Archivo modificado tras preview y código creado por otra conexión antes de cargar; snapshot y rollback integral.
4. Error SQLite durante segunda inserción/bloqueo y doble activación; carga confirmada seguida de fallo de refresco.
5. Informe seguro, no sobrescribir entrada/base/hardlinks, tamaño mínimo de ventana y deshabilitar cargas inválidas.
