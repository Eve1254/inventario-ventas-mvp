# Día 3: ventas, alertas y CSV — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. El diseño está aprobado y la usuaria solicita completar el Día 3 con pruebas y explicación.

**Goal:** Completar el MVP con venta persistida y stock atómicos, historial/detalle, avisos de existencias y exportación CSV.

**Architecture:** Extensión aditiva de `database.py`; `sales.py` procesa el carrito dentro de una única conexión/transacción y consulta el historial. `exports.py` genera archivos fuera de la transacción de venta. `sales_ui.py` y `export_ui.py` presentan historial y diálogos; POS e inventario se integran con estas operaciones.

**Tech Stack:** Python 3.14, Tkinter/ttk, SQLite, csv, pathlib, tempfile, unittest; sin dependencias externas.

**Spec:** `docs/superpowers/specs/2026-10-28-inventario-pos-design.md`.

## Global Constraints

- Conservar productos/usuarios existentes; crear ventas y detalle_venta sin recrear esas tablas.
- Precios, subtotales y total en enteros, dentro del rango SQLite; fecha ISO 8601 con zona horaria.
- BEGIN IMMEDIATE, nueva validación de existencias y precio/código, descuento condicionado a stock suficiente, COMMIT únicamente al terminar; rollback ante cualquier fallo.
- El carrito se vacía solo después del commit. No se procesa vacío ni se permite doble activación del botón.
- Stock <5 tiene aviso textual y color; cero se identifica como agotado.
- Exportar todo el catálogo y todo el detalle de ventas, independientemente de búsquedas. UTF-8 con BOM, separador punto y coma, decimales con coma y sin miles.
- Proteger campos de texto interpretables como fórmulas y evitar sobreescribir la base de datos. Cancelar el diálogo no escribe archivos; sobrescribir requiere confirmación del diálogo nativo.

## Review Focus

1. Fallo real después de modificar una primera línea: no deben quedar stock parcial, cabecera o detalles.
2. Dos carritos que compiten por las mismas unidades: solo uno puede consumir las disponibles; probar concurrencia real con conexiones independientes.
3. Error de commit/escritura, base bloqueada o carrito desactualizado: datos y carrito deben conservarse para corregir/reintentar; no confundir un fallo de refresco posterior con una venta fallida.
4. Exportación interrumpida: conservar un destino anterior y limpiar temporal; proteger destino de base/archivos auxiliares y texto de fórmulas con espacios iniciales.
5. Historial tras editar/eliminar productos: conservar instantáneas de nombre/código/precio y bloquear la eliminación de productos vendidos; la migración no borra datos previos.
